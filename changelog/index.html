    Changelog¶

    All notable changes to JATMP. Upgrade steps per version are in docs/upgrading.md.

    Unreleased¶

    Changes

    • Scam reports are now the second feed, next to cyber threats, like the two dashboards: Feed → Scams & fraud (/feed/scams), with tabs on the Feed page to switch. They left the Intelligence dropdown; /fraud/items forwards to the new address with its filters.
    • Impersonated people. Scams that borrow a public figure (a deepfake Elon Musk giveaway, mencatut nama Menteri Keuangan Sri Mulyani, fake accounts of a governor) now name that person, as a brand of the type person. A list of often-borrowed names counts next to an impersonation cue or in a sentence about a deepfake; other names only right after an office or calling ("Bupati …", "billionaire …"), so private people are left alone. The page is now called Brands & people; an impersonated person adds 8 to the fraud score.

    Fixes

    • Brands that speak or act are no longer taken for impersonated. Coinbase, which blocked $4.7 million in transfers to an Elon Musk deepfake scam, was listed as impersonated in five reports. A brand that blocks, stops, detects, reports, launches, mengajak, menilai… or opens a headline ("Indodax: …") is the actor, and a plain scam word now has to sit right next to the name ("phishing BCA"), not anywhere within 80 characters or anywhere in the title.
    • A brand's own advisory no longer names it as impersonated. "BRI Ajak Kenali Kanal Komunikasi Resmi" (customers are urged to be careful with messages mengatasnamakan BRI) reports no case: no victim, perpetrator, loss or fake going round.
    • "Anti-scam" is no scam word. "Indodax: Aplikasi Anti-Scam OJK bantu masyarakat verifikasi transaksi", about an OJK app, was filed as a crypto scam impersonating Indodax.

    • Stored items are re-analysed once after the upgrade (fraud rules version 7).

    • Newsletters and round-ups no longer flood Related items. A Cisco Talos Threat Source issue lists a CVE, a ransomware story and the same weekly "most prevalent files" hashes as every other issue, which tied it to a dozen unrelated posts. Links through such a digest now weigh far less, never join two issues of the same source, and are marked digest. A source can force or opt out with "digest": true/false in its config. Issues are recognised by tag, by title wording (bulletins, in other news, weekly threat reports, mingguan…) and by newsletter boilerplate in the body, since Talos titles like "Never be afraid to ask questions" say nothing.

    • Newsletters no longer tie unrelated things together on entity pages either. A hash from the weekly "most prevalent files" list of a Talos Threat Source issue showed up as mentioned together with VOLTA, because the same issue also covered VOLTA elsewhere (once only in a promo for another post). Digests are now flagged on the item (items.is_digest, set at collection, back-filled once after the upgrade, manage.py digesttag by hand) and Mentioned together with, the indicators of a family and the chips on the lists skip them. On an indicator's page the card is called Seen in the same items as, says that appearing in the same report is not attribution, and Linked by enrichment is shown first.
    • The relationship graph explains its lines. A second legend row shows each kind of line in the graph in its own style, with what it means and whose claim it is: Mentions (automatic), Provider link (the provider's claim), and Also mentions and Mentioned together (needs validation: co-occurrence, not a confirmed relation). Hovering a line shows the same.
    • Version numbers in advisories are no longer read as IP addresses. IBM API Connect 12.1.0.0 through 12.1.1.2, fixed builds include 17.0.21.1, 21.0.13.1, up to 1.5.1.6 and versions prior to 6.14.105.0 produced IP indicators that linked unrelated CVE posts (one "IP" sat in 69 items). A git commit in a page title ("file.py at 4fbffbc6…") is no longer taken for a SHA-1 sample hash either. Items already stored are fixed by python manage.py ioc-clean (a dry run; add --apply), which removes only the IP and SHA-1 links the extractor now rejects, and only where the item's text is still stored. Feed, AI and analyst links are never touched.
    • manage.py reextract counted mentions without flushing before it deleted orphaned entities, so an entity that only a feed linked looked unreferenced. It only deleted families and actors, so this stayed hidden; it is fixed and covered by a regression test. Note that reextract still rebuilds from the stored text, so entities that were found in the full text of an item that retention has since trimmed are not found again.

    Documentation

    • Reviewed against 0.14.0 and its new screenshots: the settings tab is called Sharing & API everywhere the docs send you to it (they said Sharing), and Using JATMP and Enrichment and verdicts describe the IOC page's Enrichment panel, Run enrichment batch and Copy visible buttons.
    • Synced with the newsletter and false-indicator fixes: Trends and correlation lists how a digest is recognised, how its links are discounted and which views leave it out (including the REST related list), and that an Also mentions line in the graph can still lead to one; Ingest and analysis covers the digest flag and the git-commit rule for SHA-1; Analysis explains the graph's line legend; Upgrading has the steps for the next release (digesttag runs once, then ioc-clean as a dry run and with --apply). The item page's card is called Correlated items, as in the interface.

    0.14.0¶

    Easier navigation: filters that stay, a grouped and collapsible menu, a New threats button, and screenshots retaken for all of it. Upgrade notes: docs/upgrading.md.

    Changes

    • Feed filters now stay when you pick another one. They are kept for your session, so choosing a language after a severity keeps the severity, and the topbar search or a chip only changes the filter it names. Clear filters is the only thing that drops them; a chip under the filter bar removes a single entity, country or province.
    • The left menu is tidier: Cyber threats, Scams & fraud and Feed stay on top, and Intelligence, Analysis and Manage are dropdowns (open when the current page is inside them, and they remember their state). The whole menu collapses to an icon rail with the arrow next to the logo.
    • New New threats button on the Intelligence lists (Malware, Threat actors, CVEs, IOCs, Scam types and Impersonated brands): it keeps only what was first seen inside the chosen period and leaves your other filters alone.
    • Every screenshot in the docs and the README is retaken for the new menu and layout.
    • Higher minimum versions of optional and core dependencies: anthropic 2.8.0, feedparser 6.0.14, python-docx 1.2.0, psycopg 3.3.9 (PostgreSQL) and telethon 1.45.0 (Telegram MTProto). Run pip install -r requirements.txt again (and the PostgreSQL or Telegram file if you use them) when upgrading from source; the Docker image installs from the lock file as before.

    Fixes

    • The default urlscan.io source searched verdicts.malicious:true, a field free accounts may not search, so it failed with 403 Forbidden. It now searches task.tags:malicious, which every plan allows. An existing source keeps its saved query: edit it under Settings → Sources.
    • Enrichment no longer fails with "UNIQUE constraint failed: entity_links" when the same indicator is linked twice in one run (for example listed by two OTX pulses). The link check now sees links added earlier in the batch.
    • Enrichment no longer ends every run with "Enrichment failed: object of type 'datetime.datetime' has no len()". The family step reused the name of the stale-verdict list for a cutoff time, so the final summary broke.

    Documentation

    • Using JATMP describes the grouped, collapsible menu, the New threats button of the Intelligence lists (and its 30-day / 7-day fallback under All time) and how Feed filters stay until cleared (only the Feed keeps them; the other lists still have Reset). Trends and correlation points from the new badge to that button. Collection and Configuration give the new urlscan.io default query and why the old one failed on free accounts. Scams and fraud points at the new menu.
    • The pages that 0.13.0 and 0.13.1 left out now describe them too. How it works: the overview's numbers table and key terms (corrections, error rate, precision and recall), enrichment (an analyst's verdict wins and keeps its date fresh), ingest (corrections respected at every step, distinctive spellings such as "RedLine" and "Cl0p", never a copy of itself), scoring (corrections re-score the item), sharing (corrected indicators in the feeds, ioc.malicious from an analyst verdict) and housekeeping (corrections kept by re-analysis and reextract, the self-copy repair, the quality gate before a rules change).
    • User guide: the docs index lists Corrections and quality; Maintenance commands documents manage.py quality and its options; Analysis has a section on corrections and rule quality and the new indicator rules (public DNS resolvers, paste and file-sharing services); Scams and fraud lists the new scam phrases and how to mark an item not a scam report; Reporting and AI explains how Q&A picks and cites items.
    • Developer pages: Extending JATMP adds the quality cases to the rules recipe, the indicator exclusion lists, topic filters and severity.RULES_VERSION; Security and Data model cover the corrections audit trail and the analyst verdict.

    0.13.1¶

    Rule tuning from the first quality report: every fix comes with the case that motivated it and counter-examples that must not change (tests/test_v0131.py, and added to tests/quality/). Upgrade notes: docs/upgrading.md.

    • Indicators: "server 91.92.243.10" is no longer mistaken for a version number; public DNS resolvers (8.8.8.8, 1.1.1.1…) are no indicators; on paste, file-sharing and code-hosting services (Pastebin, GitHub, Google Drive, Dropbox, MEGA…) the URL of a paste or file is an indicator and the service's domain is not. A defanged GitHub or Drive payload URL used to be dropped.
    • Families: a name that is also an everyday word counts without a qualifier when it is written in its own distinctive spelling ("RedLine", "Cl0p", "SafePay"); "redline" and "Safepay checkout" still don't.
    • Geography: marketplaces and hosting are no targets ("sold on Russian forums", "hosted in the Netherlands", "a Dutch hosting provider", "server di Singapura").
    • Scams: "mengaku dari Bea Cukai / polisi / bank…", fraudulent investment apps, fake QRIS stickers, SMS phishing and smishing messages, fake sellers and "jual beli online" are recognised.
    • Sectors: fuel stations and fuel supply (SPBU) are energy.
    • Severity: English service disruption (halted production, shut-down systems), the scale of a leak ("279 million records"), data put up for sale, stolen credentials and telecoms as a sensitive sector; a roundup's or guide's title gets no headline bonus.
    • Quality on the seed set (now 172 cases, with the counter-examples): families, indicators, scam, sectors and severity precision and recall 1.000; geography precision 1.000, recall 0.955 (a Dubai-based victim, a known miss). Before: families R 0.941, indicators P 0.889 / R 0.941, scam R 0.706, sectors R 0.929, geography P 0.900, severity P 0.875 / R 0.583. The rules were tuned on these cases, so read this as "the misses are fixed and the counter-examples hold", not as accuracy on live feeds; analysts' corrections will show that.

    0.13.0¶

    The rest of the product review's urgent items: analysts can correct the platform, the rules are measured, topic filters work for every source kind, and Q&A finds items by meaning it already knows. Upgrade notes: docs/upgrading.md.

    Analyst corrections

    • Analysts and admins can mark an entity as wrong on one item (✕ on the item page), mark a family, actor or indicator as wrong / not a threat everywhere, set an analyst verdict that wins over the providers, and mark an item as not a scam report. Each correction asks for a reason, is logged with the analyst's name (and in the audit log), and can be undone.
    • Corrections stay in force: re-extraction, AI extraction, the ThreatFox merge and new items skip removed links; the scam re-analysis keeps not a scam report; enrichment keeps an analyst verdict. Severity and the enrichment bonus follow.
    • New Corrections page: the log with undo, the error rate analysts reported per area over 30 days, and the names corrected most often (rules worth tuning).

    Quality measurement

    • python manage.py quality reports precision, recall and F1 of the extractor (families and actors, indicators), the scam rules, sectors, target countries and severity on labelled cases in tests/quality/, with every case the rules get wrong. First measurement on the hand-written seed set: families P 1.000 / R 0.941, indicators 0.889 / 0.941, scam 1.000 / 0.706, sectors 1.000 / 0.929, geography 0.900 / 0.947, severity (notable) 0.875 / 0.583.
    • The active corrections export as test cases (Corrections page, --corrections FILE); the report says how many analyst corrections the current rules would still repeat.
    • CI fails when an area falls below tests/quality/baseline.json and shows the report in the job summary.

    Collection

    • Topic filters (security, cyber, fraud) work for every news and social source: Telegram, X, Mastodon and Bluesky gained the Filter field. The filter runs before storing, for scheduled runs and backfills, and the run message counts the entries it dropped.

    AI

    • Q&A finds items by the entities a question names (aliases included), by malware type and sector ("ransomware on hospitals" finds "LockBit hits a healthcare provider"), by the period it names, and by each word through the full-text index; copies count once. Answers cite their items as [n] links and list what they are based on.

    Fixes

    • An original article could be marked as a copy of itself, which hid it from the feed: the one-off dedup job of 0.10.1 ran over copies that the first collector runs had already linked. find_original never returns the item itself now, and existing cases are repaired at start-up.

    Documentation

    • New page Corrections and quality; collection, AI, sources, using JATMP, development (release checklist: run the quality report), architecture and data model updated.

    • How it works and the user guide pages (getting started, configuration, using JATMP, analysis, geography, integrations, reporting and AI, history and storage, maintenance, the docs index) are rewritten in plainer, more natural language, with the behaviour of 0.11 and 0.12 throughout: copies shown once, one counting rule, the severity rules version, verdicts that age, source health, the enrichment queue and quota panel, each provider at its own pace, redaction of personal data in cloud prompts, the daily schedule's time zone, and TLP on new sources. The overview's walkthrough now follows the article to its first verdict re-check.

    • Fixes: History and storage said PostgreSQL search scans the text (it has its own full-text index since 0.10.1); Using JATMP said only VirusTotal warns about its quota; the overview said severity is never re-analysed automatically; Architecture lacked the source-health and severity re-scoring jobs and the new quota, redact and sourcehealth modules.

    0.12.0¶

    Trust and coverage items from the product review of 2026-11. Upgrade notes: docs/upgrading.md.

    Trust in the numbers

    • One counting rule. A story that several outlets carry counts once in every figure: KPI tiles and sparklines, timelines, malware / actor / sector / scam-type / brand breakdowns, target countries and provinces, entity mentions, scam report counts and the PDF / Word reports, as it already did in trend scores and the executive summary. Only per-outlet figures (Items per source, source country, language) count copies. The tile is now Stories collected and shows the item count including copies.
    • Severity rules version. When the scoring rules change, stored items are re-scored once at start-up (keeping enrichment bonuses and AI assessments), so trends never compare items scored by different rules.
    • Verdicts that age. Indicators store when their verdict was last given or confirmed and pages show "verdict as of …". Malicious and suspicious IPs, domains and URLs are looked up again after 30 days and the answer may lower the verdict (the items that mention them lose the bonus with it); after 60 days without confirmation they leave the IOC export feeds and TAXII, and STIX indicators carry valid_until. A blocklist that lists an indicator again keeps its verdict fresh. File hashes never age.

    Collection and enrichment

    • Source health on the Sources tab: last new item, items this week against the usual rate, the usual gap, how long a source has been failing, and summary only for feeds whose items carry little text. An hourly check notifies about sources that went quiet or have been failing for 24 hours.
    • Enrichment queue on the IOC page and Settings → Enrichment: indicators waiting and the oldest, arrivals against capacity per day, re-checks and stale verdicts due, and how long each daily budget lasts at the current pace with the batch size that would spread it over the day.
    • Every provider at its own pace: a run looks up its batch with one thread per provider, so it takes as long as the slowest provider instead of the sum of all of them. The per-provider gap no longer holds a lock while it waits, which made VirusTotal's 16-second gap stall every other provider.

    AI

    • Personal data out of cloud prompts: phone and e-wallet numbers, bank accounts, long ID numbers and e-mail addresses are replaced with consistent placeholders before a prompt goes to a cloud model (setting Personal data in prompts: cloud by default, always or never). IOCs, crypto wallets and amounts stay.

    Fixes

    • The dashboard, the AI settings and the docs still said the executive summary runs at 06:00 UTC; they now point at the schedule settings of 0.11.

    0.11.0¶

    Quick wins from a product review of the platform (trust in the numbers, operations). Upgrade notes: docs/upgrading.md.

    Trust in the numbers

    • Copies are visible. The feed lists each story once and says how many syndicated copies it hid; Show copies lists them with a copy badge. Item pages and previews say "Copy of original" on a copy and "Also carried by N other outlets" on the original.
    • Re-scoring no longer loses points. Re-score all items, manage.py rescore and manage.py reextract keep the indicator confirmed bonus and the last AI assessment (the AI reason now stores the severity the model proposed, so it is applied again with the same +20 cap). Before, maintenance could drop a confirmed-malicious item below the webhook threshold.
    • Running the AI analysis again on an item no longer adds its points a second time to the score, and a lower new assessment takes them away again; a suspicious indicator that turns malicious shows +12 in the breakdown (it showed +7 while the score rose by 12).

    Collection and enrichment

    • ThreatFox keeps the IOCs reported later in the day: items are keyed by the day ThreatFox first saw the IOCs (as in the backfill), and a later run adds new IOCs to that day's item, updates its count and scores it again.
    • Quota panel: Settings → Enrichment and the IOC page show the lookups used today against each provider's daily budget. The "budget used up" notification now comes for every provider with a budget, not only VirusTotal.
    • The auto-summary queue is rebuilt at start-up (live items of the last 24 hours with severity 40 or more and no summary), so a restart no longer drops the items waiting for an AI summary.

    Operations

    • Time zone and times of the daily jobs: Settings → General (or JATMP_TIMEZONE) sets the zone, the time of the AI executive summary and the time of housekeeping, and shows their next run. Defaults stay 06:00 and 03:30 UTC.
    • TLP on new sources: the Add source form asks for a TLP and says whether the source's items will be shared; Settings → Sharing counts the sources without one ("no TLP" counts as CLEAR and is shared).
    • tzdata is now a dependency on every platform.

    Documentation

    • tests/test_docs_numbers.py checks the weights, thresholds, windows and defaults quoted in How it works against the code, and the release checklist has an "update How it works" step.

    • New section How it works (docs/how-it-works/) that explains every process behind the platform with the rules and numbers it uses: an overview that follows one article from the feed to the dashboard (with real scores from the code), the scheduler's day and where each number comes from; then Collection, Ingest and analysis, Severity scoring, Enrichment and verdicts, Trends and correlation, AI processing, Sharing and delivery and Housekeeping and re-analysis.

    • Data model: syndicated copies are counted once by trend scores, scam spread and the executive summary, not by the dashboard item counts (the page said "statistics").

    0.10.1¶

    Fixes from a security, data-processing and efficiency audit. Upgrade notes: docs/upgrading.md.

    Security

    • The REST endpoint for a single entity (/api/v1/entities/{id}) returned scammer phone numbers and bank accounts; identifiers now give 404 there too, like everywhere else they are never shared.
    • The stylesheet cleaner (0.10) could backtrack exponentially on crafted text and hang a collector thread for hours. It now parses selectors without nested quantifiers and looks for rules from their declaration block, in linear time.
    • Outbound guard for every request JATMP makes on its own (feeds, WordPress and Wayback backfill, RSS-Bridge, providers, CVE intel, the AI, MISP, GeoIP, webhooks): only public addresses unless a host is allow-listed, checked on every redirect hop, connecting to the checked address (no DNS rebinding), and bodies capped after decompression (no memory exhaustion by a huge feed or a gzip bomb; the GeoIP unpacking is capped too).
    • CSV reports and the CSV IOC feed neutralise cells that a spreadsheet would run as a formula.
    • AI output is bounded: at most +20 severity, shown as AI assessment; new families from a single news item are ignored until another source reports them; AI-proposed entities and tags carry an AI badge; tags are cleaned.
    • Manual enrichment, context lookups, deep dives and AI summaries are limited per user and minute and run once per entity at a time; Run now on a source is ignored while that source runs.
    • First-run setup from another machine requires a one-time token from the log or data/setup-token.
    • API keys, the AI key and the Telegram session are stored encrypted (Fernet, key from data/config.json).
    • Changing a password, an admin resetting it, or the new Sign out other sessions button ends the user's other sessions.
    • requirements.lock pins every dependency (Docker and CI install with it), CI runs pip-audit, Dependabot is on.
    • /healthz no longer reveals the version.

    Data processing

    • Scammer identifiers need a cue that names the scammer; a generic "hubungi nomor" next to a police station, branch office or complaint line is not one. Crypto wallets must pass their checksum, and "alamat"/"address" no longer count as a crypto cue.
    • Weak scam phrases need a scam word nearby, and a malware article with one passing scam sentence is no longer a scam report. A brand that issues the warning is not counted as impersonated.
    • "Rp 2,5 T" and "Rp 5 M" are read as trillions and billions of rupiah.
    • Families and actors that are everyday words (Bitter, Patchwork, Pegasus, Oyster, Interlock…) need a qualifier; actors now follow the same rule. Demonyms and platform names ("the Indonesian ransomware gang", "Facebook malware") are no new family, a guessed family scores less than a known one, and it only trends once two sources name it. Intel-feed tags name families only on intel sources and never as everyday words.
    • Family names from providers and the AI pass the extractor's filters; Indonesian patterns also run on mixed- language items.
    • A sector needs more than one word in the title (unless the headline is about an attack on that one sector), and "bank", "rekening", "nasabah" in a scam report are the victim's bank, not an attacked finance sector.
    • Syndicated copies of a story from other outlets are marked as such: trending, spread velocity and the executive summary count the story once.
    • "critical" only scores next to a vulnerability ("critical flaw"), not in "critical infrastructure".
    • Long entry ids (URLs with tracking parameters) are hashed instead of cut at 500 characters, so they no longer collide. Re-scoring passes each link's origin, so a heuristic family scores the same as at ingest.

    Efficiency

    • Indexes on items.collected_at, items.severity and the entities columns used for sorting and filtering.
    • Item lists load their entities in one query per page instead of one per item.
    • Trending lists are cached for 45 seconds and refreshed when new items arrive.
    • AI auto-summaries run in a job of their own with a 5-minute limit instead of inside collector runs.
    • Re-score and manage.py reextract work in chunks; reextract now also rebuilds sectors and intel-tag families.
    • PostgreSQL gets a full-text index for search instead of scanning every item's text.
    • Benign-domain checks look up each parent domain instead of scanning the whole list.

    0.10.0¶

    • Two dashboards. The sidebar now opens with Dashboard → Cyber threats (the former dashboard) and Dashboard → Scams & fraud, a full dashboard of its own: scam reports over time stacked by scam type, a globe of the most targeted countries or provinces, KPI tiles with sparklines (reports, largest loss, scam types, brands, identifiers), trending scam types, impersonated brands, the latest scammer identifiers, charts by scam type, by kind of brand, by sector and by source, recent and highest-scoring reports. The scam pages moved from tabs into the sidebar under Intelligence → Scams & fraud (Scam reports, Scam types, Impersonated brands, Scammer identifiers), next to the cyber pages.
    • Dashboard period: 7 or 15 days, 30 days, 3 or 6 months, or 1 year, on both dashboards; every tile, table, chart, the radar and the globe follow it, and the choice is remembered. Charts switch to weekly bars above 90 days. Periods that reach past the live collectors show a note that older days come from the historical backfill, that not every source can be backfilled, how many backfilled items the period holds, and (for admins) a link to the Backfill page.
    • Critical infrastructure sectors: every item is tagged with the critical information infrastructure sectors of Indonesia's Perpres 82/2022 it is about (government administration, energy & mineral resources, transportation, finance, health, ICT, food, defence), from the organisations and services it names as targets, or from the sector a feed states (ransomware.live, OTX industries). Shown as a Critical infrastructure sectors chart on both dashboards (click a bar for its items), as chips on items, as a filter on the scam reports list and as sectors in the REST API. Existing items are tagged once in the background after the upgrade (python manage.py sectortag).
    • Executive summary instead of the long AI digest: a one-line headline, an overall threat level, three or four key points and up to three actions for today, asked from the model as JSON and shown with the platform's own components (no more stray markdown rules or LaTeX such as $\le$). The data it gets now includes scam types and sectors. Older digests still display as text.
    • Backfill page: Start backfill and Stop sit under the description instead of jumping around in the page header while a backfill reports progress. Stop only shows while a backfill runs, hides itself once the backfill stops, and cancels the queued sources right away; the status reads Stopping after the current page until the source being crawled finishes its page.
    • Faster scam and blocklist processing: indicators of an item are looked up and created in one query per type instead of one per indicator, and blocklist verdicts are recorded in bulk (a ScamSniffer day with 500 domains went from about 2,000 queries to a handful, which matters most for its backfill back to 2022); the scam-type spread counts are computed once per type and day per batch; Re-analyse items loads items in chunks and skips the database work for items that are not about a scam before or after (about 40% faster on a 2,300-item test copy).
    • Scam detection: vendor listicles ("Top 10 Best … Tools [Ranked & Scored]") only count their title, so a list of fraud-detection products is no longer filed as a scam report. Stored items are re-analysed once after the upgrade.
    • Fix: the scam overview's brand list styled the sidebar's logo row too (shared class name).
    • Fix: stylesheet rules that some WordPress sites print into the post text (Malwarebytes' Kadence blocks) showed up as the item's text and snippet. They are now removed when items are collected, and a one-off job cleans the items stored before (only rules made of real selectors and property: value; declarations count, so code and JSON in articles stay).
    • Scam detection: "fraud" as the name of a criminal charge ("pleaded guilty to wire fraud", bank, mail, securities, tax fraud…) no longer counts as a scam word, so an FBI agent stealing from seized crypto wallets is not filed as a crypto scam.
    • Documentation site: the docs/ pages also build a searchable MkDocs (Material) site with light and dark themes, published to GitHub Pages from main (.github/workflows/docs.yml, strict: broken links and anchors fail the build), where screenshots open full size on click. The Markdown still reads on GitHub; see Development. Every screenshot is retaken for 0.10, and the remaining "digest" labels (AI settings, report appendix, notifications) now say executive summary.

    • Enrichment.     • Correlation. Related items are ranked by evidence strength (type weight divided by log mentions, with an other-source bonus) and the shared entities are listed.
    • Feed is a table with sortable Severity, Title, Source and Time headers; the separate sort buttons are gone. Dashboard KPI tiles keep the icon link only.
    • AI settings reduced to Off / Local / Cloud, vendor and model, with presets for six local runtimes and ten cloud providers, a live model list and an advanced base-URL override. The classic LLM_* variables still work and are reflected in the new UI.
